## 1. Locked Architecture Decisions (do not relitigate)

1. **Conductor pattern, no agent framework.** A Python supervisor (`conductor/`) spawns `claude -p` subprocesses for every agent role. No LangGraph, no Agent SDK, no API keys anywhere. Auth is the machine's existing Claude Code subscription login.
2. **Per-run world isolation.** Each run gets its own uvicorn world-server instance on a port from the pool 8400-8407, started and killed by the conductor. No shared mutable state across runs.
3. **The tripwire matcher lives in world-server middleware.** All worker tool traffic is `curl` to the run's world port. Middleware (i) increments the global tool-call counter, (ii) fires the injection when the counter hits `N_inject`, (iii) evaluates the active tripwire set against each outgoing response with pure predicate matching (no LLM calls in the middleware, ever), (iv) when a tripwire matches, embeds a `tripwire_control` object in the response telling the worker to stop and escalate, and (v) appends every event to the run's JSONL trace.
4. **Escalation flow.** Worker sees `tripwire_control: {action: "STOP_AND_ESCALATE", ...}` in a tool response, terminates with a structured escalation result. Conductor detects it, calls the judge (`claude -p`, single turn). On a GENUINE verdict, conductor pauses the affected scope (terminates worker subprocesses), then resumes the orchestrator session via `--resume <session_id>` with the validated interrupt payload for a replan turn, then redispatches.
5. **System variants S1-S5** are conductor configuration, not separate codebases: S1 disables tripwires and escalation entirely; S2 instructs workers to escalate any anomaly and conductor routes it straight to the orchestrator (no judge); S3 adds a periodic orchestrator revalidation call every k worker tool-calls and no tripwires; S4 is S5 with the judge bypassed; S5 is the full protocol.
6. **Frozen artifacts.** Section 4 of this brief contains four files to be written character-for-character: `sentinel/dsl.py`, `prompts/sentinel_compile.md`, `prompts/sentinel_judge.md`, `prompts/worker.md`. Do not edit, reformat, or "improve" them. They are pre-registered experimental materials.
7. **Stack:** Python 3.11+, FastAPI + uvicorn, pydantic v2, sqlite3 (stdlib) for the job queue, pytest, Makefile as the single entry point. No other heavyweight dependencies without asking.

## 3. Milestones and Acceptance Checks

**M1: World server + injections.** All mock services up with OpenAPI specs; `/admin/inject` applies each of the 5 mutations atomically; middleware counts calls and fires injections at `N_inject`. *Accept:* pytest proves each injection changes observable behavior (404 appears, field renames, 401 on next call, contradicting passage served, gate tool returns success without running checks), and that pre-injection behavior is byte-identical across two runs with the same seed.

**M2: DSL + sentinel wrappers.** Write the frozen `dsl.py`; `compile.py` and `judge.py` construct the exact `claude -p` invocations (flags in Section 5) and parse/validate output against the DSL, with one retry on schema-invalid output (retry counted in the trace). *Accept:* `make smoke` runs a real compile on `tasks/a1.yaml`'s plan and produces a schema-valid tripwire set; malformed-output path covered by a mocked test.

**M3: Single-run conductor, S1 and S5.** `run_one.py` executes one full run end to end for batch and for full sentinel, including escalation, judge, pause, `--resume` replan, redispatch, success check, and complete JSONL trace. *Accept:* on task a1 with `endpoint_404`, S1 finishes and fails or redoes work at aggregation; S5 detects, replans, and the trace contains every event type in Section 6 of this brief.

**M4: S2, S3, S4.** *Accept:* one injected run per system on task a1 produces traces whose event patterns differ in exactly the expected ways (S2: escalations reach orchestrator unjudged; S3: revalidation calls every k; S4: tripwire fires reach orchestrator unjudged).

**M5: Queue + overnight supervisor.** SQLite job table, states pending/running/done/failed/throttled; hard `timeout` per session; throttle detection = non-zero exit with stderr matching `/rate.?limit|usage limit|overloaded|429/i`; on throttle, exponential backoff capped at 30 minutes, requeue, never crash; `make night0` enqueues manipulation checks + calibration; `make ops` prints the morning report. *Accept:* a test with a fake `claude` binary simulating throttles shows the queue surviving and resuming; kill -9 the supervisor mid-run, restart, no duplicate or lost jobs.

**M6: Metrics + gates.** `metrics.py` implements wasted work, TTD, detection recall, FIR, overhead, success exactly per protocol Section 6.1, from traces alone. `gates.py` prints the KG1-KG4 table with thresholds, and **exits with an error if the planned matrix is incomplete** (this enforces the ops-vs-science rule from protocol 8.1; no override flag). *Accept:* metrics unit-tested against three hand-constructed synthetic traces with known answers.

**M7: Phase 0 target.** `make phase0` runs the compiler on 4 designated task plans, emits tripwires plus a scoring sheet (CSV: one row per tripwire, columns for the four rubric properties, blank for hand-scoring) per protocol Section 6.4. *Accept:* produces the sheet; costs and latencies logged.

## 4. Frozen Artifacts (write character-for-character)

### 4.1 `sentinel/dsl.py`

```python
"""Tripwire DSL. FROZEN pre-registered experimental material. Do not edit."""
from enum import Enum
from typing import Literal, Optional
from pydantic import BaseModel, Field, model_validator


class Severity(str, Enum):
    CRITICAL = "CRITICAL"
    WARNING = "WARNING"
    INFO = "INFO"


class Scope(str, Enum):
    GLOBAL = "global"
    LOCAL = "local"


class Category(str, Enum):
    API_SURFACE = "API_SURFACE"
    SCHEMA_DRIFT = "SCHEMA_DRIFT"
    PERMISSION_AUTH = "PERMISSION_AUTH"
    RETRIEVAL_INTEGRITY = "RETRIEVAL_INTEGRITY"
    TOOL_CONTRACT = "TOOL_CONTRACT"


class Signal(BaseModel):
    type: Literal["http_response", "tool_output", "retrieval_content", "auth_state"]
    method: Optional[str] = None
    url_pattern: Optional[str] = None          # glob over world-server paths
    status_in: Optional[list[int]] = None
    field_absent: Optional[str] = None          # JSON pointer expected but missing
    field_regex: Optional[dict[str, str]] = None  # {json_pointer: regex}
    contradicts_assumption: Optional[str] = None  # assumption id, for retrieval checks
    order_violation: Optional[dict[str, str]] = None  # {"required_before": tool, "observed": tool}

    @model_validator(mode="after")
    def at_least_one_predicate(self):
        preds = [self.status_in, self.field_absent, self.field_regex,
                 self.contradicts_assumption, self.order_violation]
        if not any(p is not None for p in preds):
            raise ValueError("signal must contain at least one predicate")
        return self


class Action(BaseModel):
    on_trigger: Literal["PAUSE_AND_REPLAN", "ESCALATE_TO_SENTINEL", "LOG"]
    hint: str = Field(min_length=8)


class Tripwire(BaseModel):
    id: str = Field(pattern=r"^tw_[a-z0-9_]+$")
    severity: Severity
    scope: Scope
    subplan_id: Optional[str] = None            # required iff scope == local
    assumption: str = Field(min_length=12)
    assumption_id: str
    category_weights: dict[Category, float]
    signal: Signal
    action: Action
    evidence_fields: list[str] = Field(min_length=1)

    @model_validator(mode="after")
    def checks(self):
        s = sum(self.category_weights.values())
        if not (0.99 <= s <= 1.01):
            raise ValueError("category_weights must sum to 1.0")
        if self.scope == Scope.LOCAL and not self.subplan_id:
            raise ValueError("local scope requires subplan_id")
        return self


class TripwireSet(BaseModel):
    plan_id: str
    tripwires: list[Tripwire] = Field(min_length=1, max_length=12)
```

### 4.2 `prompts/sentinel_compile.md`

```
You are the Sentinel, the monitoring compiler in a three-tier multi-agent system.

INPUT: an orchestrator plan (numbered steps, each with subplan_id), the task context,
and a list of ground-truth-style assumption candidates is NOT provided; you must derive
the assumptions yourself from the plan.

YOUR JOB: compile the plan's assumptions into tripwires: typed, observable, runtime
checks that workers can evaluate with zero reasoning. Output ONLY a JSON object valid
against the TripwireSet schema provided below. No prose, no markdown fences, no
explanation. If you output anything except the JSON object, you have failed.

PROCEDURE:
1. Extract every assumption the plan depends on. An assumption is a statement about
   the world that, if false, makes a step's work wasted or wrong. Give each a short
   assumption_id (a1, a2, ...).
2. Walk the failure ontology and ask, for each category, which assumptions it
   threatens: API_SURFACE (endpoints exist, return expected status/schema),
   SCHEMA_DRIFT (field names, types, units match what steps consume),
   PERMISSION_AUTH (tokens valid, scopes sufficient), RETRIEVAL_INTEGRITY
   (retrieved passages consistent with planning premises), TOOL_CONTRACT
   (required tool steps actually executed, in order, and not silently skipped).
3. For each threatened assumption, emit at most one tripwire monitoring its most
   observable failure signal. Budget: at most 12 tripwires; prefer covering distinct
   assumptions over stacking redundant checks on one.

REQUIREMENTS for every tripwire (all four are mandatory):
- OBSERVABLE: the signal must reference concrete observables a worker's tool traffic
  produces: HTTP status codes, JSON fields by pointer, passage content, tool-call
  order. If you cannot name the concrete signal, do not emit the tripwire.
- PARAMETERIZED: concrete values, never categories. "status_in": [404, 410] is
  acceptable; "if the API changed" is a failure.
- ACTIONABLE: action.hint must name a specific replan move tied to the plan's steps.
- CALIBRATED: severity reflects blast radius (CRITICAL only if continuing wastes the
  whole scope's work); scope is local with a subplan_id unless the assumption
  underpins the entire plan; category_weights are soft and sum to 1.0.

SEVERITY ROUTING (the system depends on this): CRITICAL -> PAUSE_AND_REPLAN,
WARNING -> ESCALATE_TO_SENTINEL, INFO -> LOG. Match action.on_trigger to severity
accordingly.

SCHEMA (TripwireSet): {schema_json}

PLAN: {plan}
TASK CONTEXT: {task_context}
```

### 4.3 `prompts/sentinel_judge.md`

```
You are the Sentinel acting as escalation judge. A worker's tool traffic matched a
compiled tripwire. Decide whether this is a GENUINE plan invalidation or NOISE.

You receive: the tripwire (including the assumption it monitors), the evidence payload

Judge GENUINE only if the evidence directly violates the stated assumption in a way

  "scope_confirmed": "global" | "local",
  "affected_subplans": ["..."],
  "replan_hint": "one concrete sentence for the orchestrator",
  "reason": "one sentence, for the trace only"
}

TRIPWIRE: {tripwire}
EVIDENCE: {evidence}
PLAN SUMMARY: {plan_summary}
```

## 5. Hard Constraints on Every `claude -p` Invocation

- Always: `--bare`, `--system-prompt "$(cat prompts/<role>.md ...)"` (fully rendered, no default prompt), `--output-format json`, pinned model strings only: `claude-sonnet-4-6` (orchestrator, sentinel compile) and `claude-haiku-4-5-20251001` (workers, judge). Never aliases.
- `--max-turns`: 1 for compile and judge, 14 for workers, 6 per orchestrator planning/replanning turn.
- Worker tool permissioning: `--allowedTools "Bash(curl http://localhost:{port}/*)"` and nothing else. Compile/judge/orchestrator sessions: no tools at all.
- Every subprocess wrapped in `timeout 360`. Exit code, stderr, `session_id`, `total_cost_usd`, and per-model usage from the JSON payload are written to the trace for every invocation. If `total_cost_usd` is absent or zero under subscription, reconstruct USD from usage tokens at list prices and record both numbers.
- Orchestrator replan turns use `--resume <session_id>`, never a fresh session, so plan context persists.
- No temperature flags (unsupported in the CLI); do not simulate them.
- Record the Claude Code CLI version (`claude --version`) in every run's trace header. If the version changes mid-matrix, the queue must halt and warn.

## 6. Trace Event Schema (JSONL, one event per line)

Required fields on every event: `ts`, `run_id`, `seed`, `system`, `task_id`, `actor`, `event_type`, `payload`. Where an LLM call occurred, add `usage: {input_tokens, output_tokens, cost_usd, model, session_id}`.

`event_type` enum: `run_start, plan, compile, tripwire_set, worker_start, tool_call, tool_response, injection_fired, tripwire_fire, escalation, judge_verdict, interrupt, pause, revalidation (S3), replan, redispatch, worker_end, aggregate, success_check, run_end, throttle, error`.

`metrics.py` must compute everything in protocol Section 6.1 from these events alone; if a metric needs an event you have not emitted, fix the emitter, not the metric.
