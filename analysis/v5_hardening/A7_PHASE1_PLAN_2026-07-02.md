## 2. Design constraints — confirmed against the codebase

- **(a) Seed-derived, deterministic, byte-replayable, no wall-clock.** ✅ feasible. Use a
  dedicated `random.Random(config.seed + <A7 const>)` stream (mirrors `_auth_rng`, `state.py:322`).
  Latency is emitted as a **seed-derived integer value**, never a real `sleep`, preserving the
  invariant "no wall-clock values ever enter response payloads" (`state.py:4`). No `time.*` on any
  response path.
- **(b) Harness-only layer, same isolation as faults.** ✅ Noise fires in `WorldMiddleware`
  (`server.py:349-459`) / `_respond` (`server.py:554-647`) on the **worker counter path**, the
  same seam as `apply_injection`. It does **not** ride the read-only probe channel
  (`x-probe-channel`, `server.py:367-372`) — noise must be visible to workers to be a fair test.
- **(c) Benign by construction + qualification.** ✅ transient-500 heals (subsequent calls to the
  surface dispatch normally); additive field is unused (no required-field check reads it); latency
  is value-only (no real delay, no state change). Qualification = the ratified per-cell S1 rule
  (§3).

## 3. Qualification rule (RATIFIED — M6, per-cell)

Reused verbatim from the addendum: a noise profile qualifies for a (task × class) cell only if
**S1 (no monitor) still PASSES its checker under that noise at the cell's frozen seed**; an S1
failure **disqualifies that cell only** (V2/S2 excluded + logged; the class survives on tasks
where S1 passes). **S1 qualification runs FIRST**; V2/S2 run only on qualified cells.

## 4. Latency mechanism — the deferred decision (both options, for the author to pick)

Frozen design needs a latency class. The mock has no timing surface, so latency must be *made*
observable. Two mechanisms:

**Option (a) — seed-derived `elapsed_ms` envelope value field (author's stated lean).**
- *Build:* add an `elapsed_ms` integer to the response envelope in `_respond`, present on A7 runs
  only (gated behind `noise_profile`), baseline value seed-derived, **spiked** on the scheduled
  call. No real delay.
- *Byte-identity:* **preserved** — gated behind `noise_profile` (absent on all banked/Phase-1
  configs → `None` → field never emitted → replay 27/27 unaffected), exactly the
  `probe_channel`/`n_regions` pattern.
- *Cost:* moderate (envelope field + schedule + tests).
- *Caveat I have to flag:* `elapsed_ms`'s **mere presence** is itself an extra field, which could
  trip S2's "unexpected field" clause (`run_one.py:187-194`) and **confound latency with the
  additive-field class**. Mitigation: make `elapsed_ms` a **constant envelope present across all
  three A7 classes' runs** (so presence is constant; only its *value* spikes in the latency
  class), keeping the additive-field class's injected field distinct. Also note: **no compiled V2
  probe targets elapsed time**, so V2 latency FIR is ~0 *by construction* — an honest but largely
  pre-determined datapoint ("the monitor cannot false-fire on a signal it never observes").
- *Net:* feasible, byte-identity-safe, keeps all 3 classes; the confound is mitigable.

**Option (b) — drop the latency class as untestable-in-mock, via a numbered deviation.**
- *Build:* none. Log a deviation: "latency is untestable in the deterministic synchronous mock
  (no wall-clock, no timeout semantics, D26/D29 zero transport weather); A7 runs 2 classes."
- *Byte-identity:* trivially preserved.
- *Cost:* ~0; but shrinks the matrix to 2 classes (24 runs) and **amends the frozen 3-class
  design** (author-owned deviation).
- *Net:* cleanest honesty, but loses a pre-registered class.

**My read (supporting your lean):** Option (a) is feasible and byte-identity-safe with the
constant-envelope mitigation; it keeps the frozen design intact and yields a real (if
predictably ~0 for V2) datapoint. Recommend **(a)** with the constant-envelope mitigation, the
confound documented. **Awaiting your pick before Phase 2**; the choice is committed as a design
note.
